REA analysis targeted the matching shipped May10 2013 `eqgame.exe`, SHA-256 `2a8702ad9f722704f01355c0750be7d6f164a8b9c9128ba0cf286ea32b405b0e`. Documentation uses preferred-image virtual addresses. Sender/consumer addresses are retained in the JSON and [structure reference](STRUCTS.md).

Native evidence established packed switch row semantics, initial stance selection, AutoAssist byte57, a single final roster capacity trailer, the distinction between full period and countdown, and the unsafe mixed-unit formatter. Actual original-client runs separately verified the core gameplay/persistence cases summarized in docs/STATUS.md. They do not promote mapped-only shrouding/commerce or unresolved fields to implemented status.

The manager dispatcher is0x569920 via getter0x569b00 and outer branch0x4c53a6. Unknown cases are kept unresolved rather than named from adjacency. Raw opaque hire word upper bytes are unspecified stack content, not a discovered payment selector. Empty/no-read consumers do not establish arbitrary server reply schemas. Encoder row bounds and emulator ownership policy do not prove native account entitlement limits.

No client executable, decompiled proprietary function dump, captured packet stream or game asset is distributed. Production references describe interoperable interfaces and explicit emulator policies. Test research/helpers, generated analysis reports and logs remain outside this repository.
